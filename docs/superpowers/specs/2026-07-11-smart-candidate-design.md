# 智慧候選字功能設計

## v0.17 穩定化後的現行設計（2026-07-11）

本節是 v0.17 的現行規格。下方「初始設計」保留作為歷史決策紀錄；其中個人學習、智慧字根、記憶清除與 30 秒 timer／閒置保存等內容均已被本節取代，不可視為目前 runtime 行為。

- runtime 候選只來自 `candidate.txt`，順序固定沿用上游詞頻；不合併個人記憶，也不因選字或一般輸入改變排序。
- converter 與 `SmartCandidateTable` 載入時都只保留最多 3 個 Unicode scalar 的候選；舊版或自訂表中的超長候選會個別略過，不使整列失效。
- 候選若等於目前 context key，或目前上下文已以該候選結尾，則不顯示，避免直接疊字與自我延伸；穩定去重仍保留。
- 選取靜態候選後會更新上下文並繼續查固定表，但不呼叫 `ObserveSequence`、`RecordPredictionChoice` 或 `RecordRootChoice`。
- `candidate_memory.json` 不載入、不寫入、不清除也不自動刪除；v0.17 沒有記憶保存 timer、idle flush 或離開保存。既有記憶 class 僅保留為未啟用的未來程式碼。
- 字根候選維持原始字碼表順序，不做個人化 ranking。
- 缺少表時候選子選單只顯示下載入口；有表時只顯示總開關與連續出字兩項，不顯示智慧字根或清除記憶。
- policy v2 的一次性 migration 將總開關設為 `0`、連續出字設為 `1`、智慧字根設為 `0`；已是 v2 的設定會保留使用者後續選擇。

## 初始設計（歷史紀錄，與上節衝突時已停用）

## 目標

在不增加 DLL、NuGet 或網路背景服務的前提下，為 UCL_LIU_CSharp 加入兩種本機智慧選字：

1. 送出中文字後，依上下文顯示下一個單字或詞組。
2. 依個人選字次數，調整相同字根的既有候選順序。

例如多次正常輸入「王小明」後，送出「王」可顯示：

```text
1小明　2先生　3小姐
```

按 `Shift+1` 可一次送出「小明」，並依新的上下文繼續預測。

## 限制

- 僅使用 .NET Framework 4.5.2 與專案現有程式碼。
- 不增加 DLL、NuGet、SQLite、神經網路或斷詞套件。
- 候選查詢只走記憶體，不在 keyboard hook 熱路徑讀寫磁碟。
- 不自動下載或更新候選表。
- 個人學習資料不上傳、不連網。

## 資料來源與檔案

### 官方候選表

- 檔名：`candidate.txt`
- 格式：UTF-8 TSV，每行為一個上下文及其依序排列的候選。
- 範例：

```text
王	小明	先生	小姐
你	好	們	的	可以
今天	晚上	下午	早上
```

候選表預計由現成開放詞庫轉換產生，不手工維護。優先評估新酷音 `libchewing-data` 的 `dict/chewing/tsi.csv`；正式納入前必須逐檔確認候選資料的授權與再散布條件，並保留來源及授權聲明。

轉換時可將詞彙拆成前綴與後續字詞，例如「王小明」產生 `王 -> 小明` 與 `王小 -> 明`，並沿用來源頻率建立初始排序。

`candidate.txt` 放在專案 GitHub，另提供使用者手動下載；完整 tag 發行包直接附帶。單檔版缺少候選表時，由選單開啟：

<https://github.com/shadowjohn/UCL_LIU_CSharp>

### 個人學習資料

- 檔名：`candidate_memory.json`
- 與 `uclliu.exe` 放在同一目錄。
- 保存最近 1～3 字上下文的後續輸出統計，以及字根候選的個人選取統計。
- 候選選擇的加權高於一般輸入觀察。
- 資料只存在本機，不加入 Git。

學習先累積在記憶體。停止輸入 3 分鐘或程式正常離開時，才寫回磁碟。寫入採暫存檔完成後替換，避免中斷造成資料毀損。

## 候選排序

依下列順序合併且去除重複項目：

1. 相同上下文下由使用者明確選過的候選。
2. 從使用者一般連續輸入學到的詞組。
3. `candidate.txt` 的官方候選順序。
4. 同分候選保留原始順序，避免候選位置頻繁跳動。

智慧字根使用獨立統計，僅調整同一字根既有候選順序，不修改 `liu.json` 或 `custom.json`。

## 選單

主選單的離開項目由 12 移到 13。

缺少 `candidate.txt` 時：

```text
12. 候選字相關
    請先下載候選字
13. 離開(Quit)
```

此時只顯示下載入口，不顯示候選功能開關。點擊後只開啟專案 GitHub，不直接下載。

候選表存在時：

```text
12. 候選字相關
    【●】啟動候選字表
    【●】連續出字功能
    【●】智慧字根功能
    清除智慧選字記憶
13. 離開(Quit)
```

- `啟動候選字表` 是總開關；關閉後不顯示候選，也不新增學習資料。
- `連續出字功能` 控制送字後的後續字詞預測。
- `智慧字根功能` 控制原本字根候選的個人化排序。
- `清除智慧選字記憶` 清除個人預測與字根排序，不刪官方候選表。

設定沿用 `UCLLIU.ini` 保存。

## 操作與優先權

- 預測候選每頁最多 5 個，以 `Shift+1`～`Shift+5` 選擇。
- 第一候選從 1 開始，不使用 0。
- 有下一頁時，`Shift+Space` 優先翻頁；沒有下一頁才執行半形／全形切換。
- 選取候選後立即送字，並依新上下文繼續顯示候選。
- `Esc`、開始輸入新字根、切換英／肥模式都關閉預測候選。
- `。！？；`、Enter 與閒置 3 分鐘會結束目前上下文。
- `，` 保留上下文，讓句中預測繼續。
- 關閉預測候選不影響原本字根、注音或同音候選流程。

## UI

- 長版 UI 依當頁候選的實際文字寬度自動展開。
- 寬度不得超過目前螢幕工作區；塞不下的候選移到下一頁。
- 短版 UI 維持現有緊湊布局，不強制展開。
- 預測候選沿用現有候選標籤與數字提示，不建立新視窗。

## 錯誤處理

- `candidate.txt` 不存在：停用候選功能並顯示 GitHub 下載入口。
- 單行格式錯誤：略過該行並記錄 log，其餘資料繼續載入。
- 候選表整體無法讀取：停用候選功能，主輸入法照常運作。
- `candidate_memory.json` 損壞：改名為 `.broken` 備份後建立新記憶檔。
- 保存失敗：保留記憶體資料並記錄 log，之後再次閒置或離開時重試。

## 測試

- 解析、忽略錯誤行、合併與穩定排序 `candidate.txt`。
- 一般輸入多次「王小明」後學會 `王 -> 小明`。
- 候選選擇比一般輸入觀察取得較高權重。
- 智慧字根使常選字往前，但不改動原始字碼表。
- `Shift+1`～`Shift+5` 選字與每頁 5 筆限制。
- 有下一頁時 `Shift+Space` 優先翻頁，否則維持半／全形切換。
- Esc、新字根、英／肥切換與句尾清除候選及上下文。
- 逗號保留上下文。
- 3 分鐘 dirty save、正常離開保存、原子替換與損壞檔復原。
- 長版 UI 可展開但不超出螢幕。
- 原本字根、注音、同音候選、遊戲模式與半／全形測試不得退步。

## 第一版不做

- 雲端同步、帳號與跨裝置學習。
- 自動下載、背景更新或靜默替換候選表。
- 完整語言模型、自動斷詞與整句改寫。
- SQLite 或其他外部資料庫。
- 新候選視窗或 UI framework。
